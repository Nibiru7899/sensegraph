# Milestone 4: bounded perception feasibility gate

Frozen before fitting. Independent namespace `experiments/milestone4`; prior v2/v3 datasets, source, reports, checkpoints and budgets are hash protected. Download ledger is append-only through the existing downloader; its pre-run snapshot is retained. No old test set is opened for model selection. No new test is generated or evaluated unless the validation gate passes under a separate continuation protocol frozen before fitting any relationship model.

## Stage 1, executed before any larger experiment

Use the first 128 v3 training charts and first 30 v3 validation charts (source order, all chart types), preserving their original split. These are development data, not independent final evaluation. Seed 20261104; no hyperparameter search. Torchvision 0.23 Faster R-CNN MobileNetV3 Large 320 FPN COCO_V1, official hash-prefix-verified weights; frozen pretrained backbone/FPN and ROI feature head, trainable RPN and replacement 8-way predictor including background. Image short side 320; output boxes automatically restored to original pixel coordinates. Train AdamW lr .001, batch one, clip 1; 20 fixed-batch smoke steps, then reset to the same initialization and 240 development steps. No selection among checkpoints: use final step. Frozen ROI embeddings provide a 1024-D image-only feature interface. All sessions include overhead, reserve up to 600 seconds against the remaining lifetime 3600-second budget, and retain incomplete reservations. No mixed precision.

Ontology: bar, point, line_segment (enclosing rectangle, not segmentation), text (title/axis_label/tick_label), legend_item (text only, not whole legend), axis, tick. Series unions are excluded from detector supervision and remain unobservable unless a later independently specified grouping module predicts them. Boxes must be finite, positive-area, within original image; invalid boxes are reported, never silently padded. Thin axis/tick/segment targets remain included with original extents; small-object limitations must be reported. Raw node types are used only to construct supervision, never at image-only inference.

One-to-one greedy confidence-ordered matching, exact detector-class compatibility, IoU >= .50 and .75. Per-class precision/recall at confidence .25; all-score interpolated area-under-precision-envelope AP (not COCO 101-point mAP), with missed objects in denominators. Report normalized center error for matches, unmatched detections, duplicate detections, total GT coverage and unsupported types. AP ties use deterministic original prediction order; disclose this convention. Validation gate requires macro recall@.50 >= .50, macro AP@.50 >= .30, and both point and segment recall >= .20. Failed gate: **stop and report the learned-detection bottleneck**, preserve checkpoint and all evidence. Do not substitute oracle relation scores for non-oracle performance. No tuning after observing the gate.

Before development fitting: one-image inference, finite loss/gradients, fixed-batch loss check, reload/repeated inference equality, predicted overlay review, empty/duplicate proposal graph tests and matching tests. Guard failures stop the run. Record per-image perception latency including image decoding, graph construction and embedding extraction; CUDA memory is allocated/reserved PyTorch memory, not whole-device usage. Image decoding and metrics may conservatively be charged GPU-session wall time.

## Conditional later stages (not authorized to bypass the gate)

Only if detection passes, freeze a continuation with new independent held-out styles/numerical configurations, train/validation-only feature/relationship selection and test inventory hashes before opening final data. Planned main matched MLP/GATv2 comparisons use geometry/RGB, +frozen ROI features, +trainable visual projection, then learned proposals; complete GAT connectivity and spatial-six are predeclared. Seeds 42/43/44 subject to remaining budget. Same inputs, optimizer, maximum steps and comparable parameter budgets. All ten relationships remain visible. No current M3 architecture is fed 1024-D embeddings without a separately versioned input projection.

Evaluation utility must count every missed GT relation as FN and every unmatched predicted relation as FP, as well as conditional F1 restricted to uniquely matched endpoints. Duplicate proposals never gain a second GT match. Unobservable series nodes remain in end-to-end GT relation denominators, not silently removed. Node matching uses compatible detector categories, never numerical values or relations. Unknown real annotations remain masked.

Controlled proposal perturbations would use independent seeds 101/102/103 and levels 0/.05/.15/.30 for normalized coordinate jitter, missing nodes, duplicates, uniform false boxes, crop appearance noise, and OCR character corruption. These are explicitly oracle-derived diagnostics, never learned-detector evidence. They are deferred if the gate fails, as are three-seed graph training and any final-test claims.

Local OCR adapter uses an installed Tesseract executable only, with separate transcription and confidence; no source text is inserted when unavailable. Rotation/negative/decimal/numeric/categorical recognition accuracy requires independently matched trusted text and is **unmeasured** until executed. No OCR engine download is implicit. OCR/model choices beyond this gate require provenance and counted acquisition. ChartQA's 20 partial training examples are development-only; no automatic mixing with complete synthetic negatives. VisText raster transform remains unknown. A credible real held-out set needs independent reviewers, label coverage policy and image rights review; none is claimed here.
